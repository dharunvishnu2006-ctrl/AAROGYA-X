# the first FHIR export
# Modules: M2 HIS (begins), M1 EMR (export), platform
# Twins: CloudShield v1.1 (Flask alert API),
#        Sentinel v1.1 C9 (REST clients for both flagships)
# Updated 17 October 2026: tasks 7-10 added (journey test, FHIR export)

## Goal
Replace the meaningless occupancy figure with one based on real stays,
expose the dashboard's data through a small read-only API, prove one
patient's whole journey in a single test, and let another system read
a patient's record in the world standard format (FHIR) - export only.

## Build in two parts
Part A = tasks 1-6. Run python scripts/check.py and review.
Part B = tasks 7-10, only after Part A is green and reviewed.

## Tasks - Part A
1. aarogya/m2_his/: one Hospital class (id, name, city, total_beds) and
   a "stays" table in the clinical store: stay_id, patient_id (FK),
   hospital_id, ward, bed, admitted_at (UTC), discharged_at (UTC or NULL).
2. Stay rules: a patient cannot have two open stays; a bed holds at most
   one open stay; discharge must be after admission; a patient never
   admitted cannot be discharged. Violations raise a clear error.
3. Occupancy per hospital = open stays / total_beds, shown per hospital.
   Above 100% is shown and flagged - never clamped.
4. data/generate_data.py also generates synthetic hospitals and stays
   for the sample patients (fixed seed). Loading runs extract ->
   validate -> load, logging the counts (no patient data in logs).
5. aarogya/platform/api.py (Flask), read-only, bound to 127.0.0.1:
   GET /health               -> the B1 health result
   GET /cohort/stats         -> cohort_stats summary
   GET /patients/<patient_id> -> id, age band, city, vitals, risk
                                (no name)
   GET /hospitals/occupancy  -> per hospital
   Routes are thin: parse, validate, call one function, return JSON.
   Bad id -> 400 with the format message. Unknown id -> 404.
   Never a 500 from deep inside.
6. design.md: "No authentication yet - API is localhost only" as a
   known limit.

## Tasks - Part B
7. aarogya/m1_emr/fhir_export.py: patient_bundle(patient_id) returns a
   FHIR Bundle (type "collection") built only from what the store holds:
   - Patient: id = patient_id, gender, address.city. NO name.
     No birthDate - the record has age only (birthDate comes in v2).
   - Observation per vital, subject "Patient/<id>", status "final",
     effectiveDateTime = the stored UTC time, standard LOINC codes and
     UCUM units: blood pressure as one panel with systolic and diastolic
     components; BMI; fasting glucose. Category: vital-signs for BP and
     BMI, laboratory for glucose.
   - Encounter per stay: class inpatient, period start/end from the
     stay, status in-progress while open, finished after discharge.
   Plan: name the validator library, the FHIR version it validates,
   and every LOINC code you will use. Dharun checks each code on
   loinc.org before approving.
8. API: GET /patients/<patient_id>/fhir -> the Bundle as
   application/fhir+json. Same 400 / 404 rules. Every resource in it
   passes the validator in a test.
9. tests/test_patient_journey.py - ONE test, one synthetic patient,
   the whole v1.1 hospital in order (store in tmp_path):
   upload one CSV row through the real reader -> stored and validated
   -> risk band assigned -> admitted to a bed -> that hospital's
   occupancy rises by exactly one bed -> GET /patients/<id> shows it,
   no name -> GET /patients/<id>/fhir has the Patient, its Observations
   and an in-progress Encounter -> discharged -> occupancy back,
   Encounter finished -> the log file has no patient_id in it.
10. Known limits "FHIR export only - no import yet (v2); not tested
    with any other hospital system; no connection to ABDM":
    I add these to design.md myself. Do not edit design.md.

## Must not
- Compute occupancy from city.
- Return a patient name from the API or in the FHIR export.
- Put a value in the FHIR export that the store does not hold
  (no invented birthDate, no invented codes).
- Use SQL joins (Layer 3) - keep queries single-table.
- Call the export "ABDM-compliant" or "certified" anywhere.

## Allowed tools
sqlite3, flask, json, datetime, random (seeded), pandas,
fhir.resources (Pydantic-based validator - ask before installing,
pin the version).

## Verification
- Patients in Chennai but no open Chennai stays -> Chennai 0%, not
  "patients / beds".
- Admit the same patient twice -> refused. Discharge a never-admitted
  patient -> refused. Discharge before admission -> refused.
- GET /patients/PX01 -> 400 with format message; /patients/P999 -> 404;
  /health -> reflects the store's real state.
- GET /patients/P007/fhir -> a Bundle that passes the validator; no
  name anywhere in it; Observation and Encounter references point to
  Patient/P007.
- The journey test passes on its own: pytest tests/test_patient_journey.py
- Flask test-client tests for every route; no network needed.

## Out of scope
Transfers between wards, waiting lists, login, FHIR import and
matching records from other systems (v2), real ABDM connection.
