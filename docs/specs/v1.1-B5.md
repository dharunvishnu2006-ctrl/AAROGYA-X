## Goal
A simple, clean Overview that looks like hospital software - sidebar
menu, KPI cards, occupancy, patient flow, recent patients, what needs
attention - where every panel reads real (synthetic) data from the
store, and every module not built yet is listed, closed, with the
version that brings it. Nothing fake works. Less on screen, more space.

## Tasks
1. Navigation: st.navigation + st.Page. app.py becomes a thin entry
   (page config, logging, bootstrap, health, navigation). One page per
   file in ui/ :
     Overview            the dashboard below
     Patients            directory + risk lookup
     Beds & occupancy    per hospital, over 100% flagged (B4)
     Risk & statistics   cohort stats, groups, charts (B3)
     Records             upload + record correction + history
     System health       the B1 health result in full
   Every existing feature lives on exactly one page. Nothing is lost.
   Sidebar foot: "AAROGYA X v1.1" and the health status in one line
   (e.g. "System healthy"); the details stay on System health.
2. aarogya/m15_dashboard/kpis.py - pure functions, no Streamlit,
   each takes hospital_id=None (None = all hospitals):
   - overview_kpis -> patients, inpatients (open stays), high_risk,
     beds_total, beds_occupied, beds_available, occupancy_pct,
     over_capacity (hospital names). high_risk uses the existing risk
     scorer - no new threshold. beds_available = sum over hospitals of
     max(beds - open, 0). Occupancy is never clamped.
   - recent_patients(n=8, status=all|open|discharged) -> newest stays
     first: admitted (IST), patient as Patient.__str__ from B2
     ("P007 - Pushti J."), hospital, ward, bed, status.
   - patient_flow -> per day: admissions, discharges, over the date
     range the stays really cover (pandas groupby on the date).
   - needs_attention -> high-risk patients (id + B2 display, up to 10)
     and hospitals over 100%.
   Hospital names are looked up in Python - no SQL joins.
3. Overview layout - THREE rows only, generous spacing, one number
   and at most one short caption per card:
   Row 1  Header "AAROGYA X - Hospital platform" with a hospital
          selectbox (All hospitals + each one) and a patient search by
          patient_id on the same line (B2 format check; bad id -> the
          format message; unknown -> "not found"; found -> id, name,
          age band, city, risk, stay). Caption: "Synthetic data - not
          for clinical use". Below it, five st.metric cards: Patients,
          Inpatients, High-risk, Beds occupied, Beds available.
          No delta ("vs yesterday") - the data has no real today.
   Row 2  Two columns: (left) occupancy donut - a new function in
          m15_dashboard/charts.py (matplotlib, theme-aware like B3,
          with a test): occupied vs available, the real % in the
          centre; st.warning names any hospital over 100%.
          (right) patient flow (st.line_chart): admissions and
          discharges per day; caption = the date range of the stays.
   Row 3  Two columns: (left) recent patients, tabs All / Inpatients /
          Discharged. (right) needs attention: the high-risk list,
          labelled "Rule-based thresholds - not a prediction model",
          and any hospital over 100%.
   Then one closed st.expander "Coming next - 10 modules": a plain
   list, each "<module> - arrives in vX", no numbers, nothing
   clickable: Laboratory, Pharmacy, Emergency triage (v2) - Medical
   imaging, Risk prediction model (v3-v4) - AI clinical assistant,
   OPD and appointments, Login and roles (v5) - Billing, Command
   centre (v6).
   Footer caption: "Decision support only - the clinician decides."
4. Theme: .streamlit/config.toml [theme] base "light", one
   primaryColor (a calm teal or blue), font. Dark must stay readable
   (Settings -> Theme).
5. docs/design/target_look.png with its caption in design.md
   ("AI-generated mockup of the target look (v6). Not the current app.
   Its numbers, alerts and compliance lines are not real."):
   I add both myself. Do not edit design.md.
6. Tests: tests/test_kpis.py on a store in tmp_path with known
   patients and stays -> exact counts for all hospitals and for one;
   over capacity -> beds_available never negative, hospital listed;
   flow: 2 admissions day 1, 1 discharge day 2 -> exact rows; recent
   order and the three status filters. tests/test_pages.py
   (streamlit.testing AppTest): every page runs with no exception;
   Overview metric values equal overview_kpis on the same store;
   the Coming next expander contains no st.metric.

## Must not
- Show a number that does not come from the store. No sample KPIs,
  no "vs yesterday", no OPD, lab, pharmacy, billing or appointment
  figures - v1.1 has none.
- Give a Coming-next module a number, a page or a link.
- Use the words AI, ML, predictive or model for the rule-based risk.
- Show a doctor's name or a login - v1.1 has no users.
- Claim compliance or security anywhere (no "HIPAA", "DPDP",
  "Secure", "Compliant").
- Compute length of stay - its one definition is decided in v2 B4.
- Use SQL joins (Layer 3), unsafe_allow_html, or add any package -
  streamlit, matplotlib and pandas are already in requirements.txt.
- Put a patient name in a log line or the API (names stay in the app).
- Change any clinical rule, threshold, risk result or API route.
