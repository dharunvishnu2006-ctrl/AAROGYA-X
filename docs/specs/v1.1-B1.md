# v1.1 B1 — Platform foundations
# Modules: M14 audit, M15 ops, platform
# Twins: CloudShield v1.1 (JSON logging + run_id),
#        Sentinel v1.1 C2 (logging) and C10 (engineering discipline)

## Goal
Make the codebase safe to grow: module folders, tests that pass from
any directory, a clean requirements file, one quality-gate command,
and structured logs plus a health check that tell the truth.

## Tasks
1. Module layout (package "aarogya"):
   aarogya/m1_emr/        models.py, clinical_store.py
   aarogya/m2_his/        hospitals.py (ONE Hospital class; remove the
                          copies in app.py and models.py)
   aarogya/m6_risk/       clinical_config.py, analytics.py
   aarogya/m14_audit/     logging_setup.py, health.py (new)
   aarogya/m15_dashboard/ charts.py
   aarogya/platform/      paths.py (new: every path from the project
                          root with pathlib)
   app.py stays at the repository root. tests/ mirrors the tree.
   Update every import. Behaviour stays the same.
2. Tests from anywhere (D3): no test depends on the working directory
   or on data/aarogya.db. Tests that need data build it in tmp_path.
   Shared setup in tests/conftest.py fixtures.
3. requirements.txt (D5): UTF-8, only packages the app imports.
   requirements-dev.txt: pytest, black, flake8, mypy, bandit.
   Re-save .gitignore as UTF-8; keep every rule.
4. scripts/check.py: runs black --check, flake8, mypy, bandit -r aarogya,
   pytest; prints one line per tool (PASS/FAIL); exits non-zero if any
   fails. Must work on Windows and Linux.
5. Logging: JSON lines to logs/aarogya.log (rotating, UTF-8, gitignored).
   Fields: time (UTC ISO-8601), level, event, module, run_id.
   Events: app_start, seed_loaded, upload (rows_read, accepted,
   rejected), correction_saved, error.
6. Health: health() returns status (healthy/unhealthy), store_reachable,
   patient_count, last_upload_utc. Shown in the sidebar. Unhealthy when
   the store cannot be opened or queried.

## Rules
- No log line contains a patient name, patient_id or vital value.
- Health is computed live from the store; never a fixed "ok".

## Must not
- Change any clinical behaviour, threshold or risk result.
- Lose any of the 27 existing tests (they move; they still pass).
- Add a dependency beyond Layer 1 (step 80).

## Allowed tools
pathlib, logging (RotatingFileHandler), json, uuid, sqlite3,
subprocess, pytest, black, flake8, mypy, bandit.

## Verification
- pytest passes from the repo root AND from inside tests/.
- python scripts/check.py: all PASS; break one line's formatting ->
  it exits non-zero.
- After one app run + one upload, logs/aarogya.log has JSON lines;
  search it for "P0" and for any sample name -> 0 hits.
- Rename data/aarogya.db while the app runs -> health shows unhealthy.
- requirements.txt is UTF-8; every line matches a real import.

## Out of scope
GitHub CI, packaging, branch-per-feature workflow.
